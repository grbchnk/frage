# ВИКТОРИНА У АЛИНЫ ДОМА

Викторина для друзей: 20 категорий, 100 вопросов, два раунда. Телефон — пульт ведущего, телевизор или компьютер — общий экран. Сайт статический, работает на GitHub Pages. Supabase хранит одну партию и передаёт изменения между устройствами. Отдельный сервер и Render не нужны.

## Что уже работает

- Ввод 2–10 игроков, очередь выбора вопросов, ответить может любой.
- Начисление 100–500 баллов, раскрытие ответа только после решения ведущего, вариант «никто не угадал».
- Фотографии, временные плашки с раскрытием полного кадра, визуальные ребусы.
- Перерыв на 10 минут, второй раунд, финальная таблица, общая победа при равенстве очков.
- Отмена последних действий (до 30 в текущем сеансе пульта), возврат неразыгранного вопроса.
- Полная игра на 100 вопросов или 60 вопросов: три любых в каждой категории.
- Оригинальная музыка поля, отдельная музыка вопроса, звуки открытия, ответа и финала через Web Audio.
- Сохранение игры при перезагрузке, Realtime и резервное обновление раз в 5 секунд.
- Проверка версии при записи: два пульта не перезаписывают друг друга, двойное нажатие не удваивает баллы.

## Один раз настроить Supabase

Проект: `gvxnevignfgsysmahytm`. Публичные URL и publishable key уже в `.env.example`. Они предназначены для браузера. **Никогда не добавляйте secret/service_role key в сайт, GitHub или переменные VITE_ / NEXT_PUBLIC_.** Если секретный ключ был отправлен в чат, отзовите его в настройках API-ключей проекта.

### 1. Создать таблицы и загрузить ответы

После `npm ci` выполните `npm run prepare:content`. Он создаёт файл **supabase/setup.sql**.

Откройте Supabase → **SQL Editor → New query**, вставьте всё содержимое этого файла и нажмите **Run**. SQL создаст:

| Таблица | Для чего | Доступ из сайта |
| --- | --- | --- |
| `quiz_game` | Единственная партия `main`: игроки, очки, вопрос, раунд | Все читают; ведущий обновляет |
| `quiz_answers` | 100 правильных ответов и заметки | Только ведущий читает |
| `quiz_hosts` | Разрешённые аккаунты ведущих | Пользователь видит только собственную запись; менять список из сайта нельзя |

Также SQL включает RLS, выдаёт точные разрешения и добавляет `quiz_game` в публикацию Realtime. Повторный запуск сохраняет партию и ведущих, обновляя ответы. Ручное создание столбцов в Table Editor не требуется.

### 2. Создать аккаунт ведущего

Supabase → **Authentication → Users → Add user → Create new user**. Укажите свою почту и придумайте пароль; включите **Auto Confirm User**. Пароль остаётся у вас, присылать его не нужно.

Затем откройте **supabase/add-host.sql**, замените `YOUR_EMAIL@example.com` на эту почту и выполните файл в SQL Editor. Это разрешает аккаунту управлять игрой. Простая регистрация другого пользователя прав ведущего не даёт.

На телефоне войдите с этой почтой и паролем. Supabase JS сохраняет и обновляет сеанс в браузере; серверные cookies, Next.js middleware и `@supabase/ssr` здесь не используются, потому что GitHub Pages обслуживает статические файлы.

### 3. Проверить соединение

Откройте сайт на телефоне и компьютере. На обоих должен появиться статус «В эфире». Запустите игру на телефоне: экран компьютера должен показать имена и поле. Если таблица ещё не создана, сайт покажет сообщение с кодом ошибки. В Supabase → Database → Publications проверьте, что `quiz_game` включена в `supabase_realtime`, если Realtime не подключился; резервное обновление продолжит работать.

## Локальный запуск

Node.js 24, npm.

```powershell
npm ci
Copy-Item .env.example .env.local
npm run prepare:content
npm run dev
```

Адрес: http://localhost:5173/ . Для репетиции без Supabase:

- Пульт: http://localhost:5173/?mode=host&demo=1
- Экран: http://localhost:5173/?mode=display&demo=1

Демо синхронизирует вкладки **одного браузера**, не разные устройства. Демо и его endpoint с ответами доступны только в dev-сервере; в production-сборку они не попадают. Для телефона и телевизора используйте обычный режим через Supabase.

```powershell
npm run build
npm test
npm run preview
```

Готовый сайт — папка `dist`. Сборка сохраняет только используемые фото, уменьшенные до 1600×1200 внутри исходных пропорций. Исходники не меняются. Ответы не включены в публичный JSON вопросов или JavaScript приложения: они загружаются ведущим из защищённой таблицы. При открытии исходного репозитория ответы всё же доступны в редакционном пакете; это домашняя викторина, не система противодействия поиску ответов.

## GitHub Pages

В репозитории **Settings → Pages → Build and deployment → Source → GitHub Actions**. Workflow `.github/workflows/pages.yml` установит зависимости, подготовит контент, соберёт сайт, выполнит тесты и опубликует `dist` при пуше в `main`.

Публичная конфигурация берётся из `.env.example`. Если меняете Supabase-проект, обновите URL и publishable key в этом файле. Секреты для сборки не нужны. Относительные пути поддерживают размещение в `/frage/`.

Ожидаемый адрес после публикации: https://grbchnk.github.io/frage/

## Как провести вечер

1. На телевизоре открыть сайт и один раз нажать кнопку ноты: браузер требует нажатия для включения аудио. Громкость доступна внизу. При желании включить полный экран.
2. На телефоне открыть тот же адрес. Телефон обычно выбирает пульт автоматически; кнопка «Пульт» / «Экран» позволяет переключить режим. Для надёжности можно использовать `?mode=host` и `?mode=display`.
3. Войти, ввести имена по порядку выбора, выбрать 100 или 60 вопросов, начать.
4. Нажать стоимость выбранного вопроса. Ответ виден только на пульте. Таймер информационный: истечение времени не закрывает вопрос.
5. Нажать имя ответившего или «Никто не угадал». Всем откроется ответ. «Продолжить» закрывает вопрос и передаёт выбор следующему по исходному списку.
6. После всех вопросов первого раунда появится перерыв. Ведущий запускает второй раунд, когда все вернутся. Можно продолжить раньше; таймер сам игру не запускает.
7. Если вечер затянулся, «Закончить раунд» с подтверждением пропустит остаток и сохранит очки.

Отмена работает до перезагрузки пульта. После действий с другого пульта история отмены сбрасывается во избежание перезаписи чужих действий. При обрыве сети новое действие не считается сохранённым до ответа базы; после неоднозначной ошибки сайт запрашивает актуальную партию.

## Контент и проверка

Редакционный оригинал: `quiz-pack.json`, полный список для ведущего: `ВИКТОРИНА_100_ВОПРОСОВ.md`. После правок выполните `npm run build` и повторно загрузите `supabase/setup.sql`, чтобы обновить ответы в базе.

Фоторебусы используют отдельные настоящие фотографии и знаки поверх интерфейса. После обновления пакета пульт проверяет версию ответов в Supabase: со старой версией он не даст случайно начислить баллы за чужой ответ. Выполните свежий `supabase/setup.sql` и перезагрузите пульт. Редакционные Markdown/HTML-документы и перечень использованных фото пересобираются из `quiz-pack.json` автоматически. Скрипты `research/build_pack.py` и `research/expand_pack.py` сохранены как история первоначального исследования; их запуск перезапишет пакет старой версией.

100 вопросов могут занять 100–140 минут с обсуждениями. Для 60–90 минут лучше режим на 60 вопросов и короткие обсуждения.

Тесты проверяют полный игровой вечер, сокращённый режим, очередь, повторные начисления, изоляцию заметок ведущего, а также SQL и RLS на настоящем локальном Postgres-движке PGlite: зритель, посторонний пользователь, ведущий, повторный запуск setup и запись с устаревшей версией. Они не заменяют проверку двух физических устройств на подключённом Supabase-проекте.

Лицензии фотографий доступны в игре («Фото и авторы») и в `assets/ИСТОЧНИКИ_ИЗОБРАЖЕНИЙ.md`. Музыка синтезируется приложением без сторонних записей.
