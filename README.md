# Кто первый?

Домашняя викторина: телевизор — общий экран, телефон или компьютер ведущего — пульт, телефоны участников — кнопки. Статический сайт на GitHub Pages; Supabase хранит партию и атомарно определяет первое нажатие. Отдельный сервер не требуется.

## Правила

- В основном банке 76 категорий и 396 вопросов. Финальные темы и вопросы хранятся отдельно.
- Перед стартом ведущий выбирает режим: любое число случайных категорий без повторов или темы, отмеченные галочками вручную. Поле из более чем десяти тем разбивается на страницы. Страницы переключает ведущий для всех экранов. Выбор сохраняется в партии и одинаков на всех устройствах.
- Ведущий включает нужные типы, включая отдельный фильтр для обычных вопросов с картинками. Из подходящих вопросов каждой темы случайно выбираются пять без повторов, сортируются по исходной цене и занимают ячейки 100–500. Очки считаются по цене ячейки. Темы с менее чем пятью подходящими вопросами недоступны. Можно сыграть все пять или закончить тему после трёх вопросов.
- От 2 до 10 игроков. Участник входит по имени, без пароля. Повторный вход с тем же именем возвращает к тому же игроку.
- Первый подключившийся выбирает первый вопрос. Затем выбор переходит к последнему правильно ответившему.
- Кнопки доступны с открытия вопроса, в том числе во время печати текста.
- Первая принятая базой заявка получает право ответа. На телевизоре появляется имя, звучит сигнал; остальные кнопки блокируются.
- У ведущего две большие кнопки для текущего отвечающего. «Правильно» начисляет стоимость вопроса и сразу раскрывает ответ. «Неправильно»: списывается половина стоимости вопроса, кнопки снова доступны всем. Тот же игрок может снова отвечать на вопрос. «Снять нажатие без штрафа» открывает кнопки всем и сохраняет очки. Счёт может уйти в минус. Рядом со счётом остаётся небольшая плашка +/− за последний вопрос. Она суммирует все попытки конкретного игрока за вопрос. Ручная поправка меняет общий счёт. Штраф и переключение кнопок сохраняются в одной транзакции, отмена восстанавливает прежние очки и право ответа.
- Если никто не ответил, ведущий может раскрыть ответ без начисления баллов. После «Продолжить» вопрос считается сыгранным.
- В «Кто ближе?» сравниваем абсолютную разницу с эталоном. Ближайшие получают стоимость, самые далёкие теряют половину. При равном отклонении у ответивших штрафа за дальность нет. Таймер на 25 секунд включён по умолчанию и отключается в настройках матча. При таймере результаты открываются автоматически. Каждый пропуск по времени отнимает половину стоимости. С выключенным таймером ведущий закрывает приём вручную.
- В «Вариантах по очереди» выбирающий ходит первым, остальные идут по убыванию очков. Вариантов на один больше числа игроков, неверный вариант исключается, верный завершает вопрос.
- В общих вариантах и сортировке каждый отвечает на телефоне. Верный ответ даёт стоимость, неверный отнимает половину. До раскрытия общий экран показывает только отметки об ответах. Ведущий может завершить приём заранее.
- Если в «Кто первый?» задана подсказка, отвечающий может открыть её на ТВ. Все последующие ошибки на этом вопросе стоят полную стоимость.
- Включённый финал предлагает лидеру выбрать отдельную тему. Все ставят от нуля до своего положительного остатка, затем отвечают письменно. Ведущий закрывает приём, проверяет ответы и показывает ставки, результаты и победителей.
- Отмена последних 30 действий действует до перезагрузки пульта. Возврат к вопросу открывает новое окно нажатий.

## Настройка и обновление Supabase

Проект: `gvxnevignfgsysmahytm`. Публичные URL и publishable key находятся в `.env.example`. Секретные ключи в клиентский сайт не добавлять.

```powershell
npm ci
Copy-Item .env.example .env.local
npm run build
npm test
```

Для установки и обновления версии с новыми типами выполните **весь `supabase/setup.sql`** после сборки в Supabase → SQL Editor. Он включает функции общих ответов, ставки, подсказки и актуальный банк. Пульт запрашивает ответ к открываемому вопросу по его ID. Повторный запуск сохраняет текущую партию. После обновления клиента начните новую игру. Для последующих правок только контента уже на этой схеме достаточно свежего `supabase/update-answers.sql`.

| Таблица | Содержимое |
| --- | --- |
| `quiz_game` | Одна партия `main`: игроки, очки, выбранные темы, вопрос и версия записи |
| `quiz_answers` | Ответы и заметки для гостевого пульта через `quiz_host_answers` |
| `quiz_hosts` | Аккаунты из предыдущей версии |
| `quiz_participants` | Имена и идентификаторы подключившихся в лобби |
| `quiz_buzzer` | Текущий вопрос, уникальное окно нажатий и первый игрок |
| `quiz_private.submissions` | Введённые ответы и ставки. В общей записи партии публикуются только отметки о сдаче до закрытия, затем результаты |

Пульт открывается по `?mode=host`, игроки входят по имени через `?mode=player`. Все подключаются к одной общей партии. Любой посетитель, который откроет пульт, получает доступ к ответам и управлению этой партией.

Гостевые RPC `quiz_save`, `quiz_restore`, `quiz_rearm` и `quiz_release` проверяют версию партии. При оценке ответа проверяется текущее окно нажатий. Обновление партии и изменение состояния кнопок выполняются в одной транзакции. Запоздавшее нажатие со старым идентификатором окна не может выиграть новый вопрос. Нажатия сами по себе не меняют версию партии.

Supabase Realtime используется для партии, участников и кнопок; есть резервное чтение. Побеждает первая заявка, принятая базой, поэтому скорость соединения влияет на результат. Для домашнего вечера подключите все устройства к одному Wi-Fi. На реальных телефонах обязательно проведите короткую репетицию.

## Запуск и режимы

```powershell
npm run dev
```

- Телевизор: `http://localhost:5173/?mode=display`
- Пульт: `http://localhost:5173/?mode=host`
- Участник: `http://localhost:5173/?mode=player`

На маленьком сенсорном экране по умолчанию открывается участник. С телефона пульт можно открыть и с экрана входа игрока. В лобби телевизора и пульта есть QR-код и ссылка для игроков. Для других устройств используйте сетевой адрес компьютера вместо localhost либо опубликованный сайт. Камера телефона может открыть QR-код в отдельном браузере — войдите с тем же именем.

Демо: добавьте `&demo=1` к любой ссылке в dev-сервере. Оно синхронизирует вкладки **одного браузера**, включая одновременные нажатия через Web Locks. Разные устройства связываются через обычный Supabase-режим. Демо-ответы в production не публикуются.

На телевизоре нажмите ноту, чтобы включить музыку и сигналы. Экран участника показывает имя, счёт за игру, изменение за вопрос и статус. Кнопка серая в ожидании, янтарная для открытого вопроса, красная пока отвечает другой игрок и зелёная у отвечающего. После оценки ответа на телефоне и общем экране появляется соответствующая вспышка. Вопросы печатаются по буквам с сохранением раскладки текста. При настройке reduced motion текст показывается сразу.

## Контент

Источник — `quiz-pack.json`. После его изменения выполните `npm run build`, а для обновления ответов в удалённой базе повторно выполните `supabase/setup.sql`.

У вопросов без `type` используется обычная кнопка. Можно добавлять несколько вопросов с одной стоимостью в одну категорию. Для каждого нужен уникальный `id`. Картинки задаются через существующее поле `media` независимо от типа.

| Поле `type` | Что добавить к вопросу |
| --- | --- |
| `buzzer` | При необходимости `hint` |
| `estimate` | Числовой `target` и, при необходимости, `unit` |
| `turns` | Ровно 11 строк в `options` и индекс правильной строки в `correctOption`, начиная с нуля |
| `choice` | От 2 до 4 строк в `options` и индекс `correctOption` |
| `order` | Подписи карточек в `options` и правильная перестановка их индексов в `correctOrder` |

Для финала добавляйте темы в `finals`: у каждой свой `id`, `title` и массив `questions` с уникальными `id`, `prompt`, `answer`, необязательными `accepted_answers` и `explanation`.

Генератор создаёт:

- `public/content/questions.json` — вопросы без ответов и заметок;
- `public/media` — используемые изображения, сжатые в WebP;
- `supabase/setup.sql` — схема, функции кнопок и ответы с версией пакета;
- `ВИКТОРИНА_БАНК_ВОПРОСОВ.md` и `ПРОСМОТР_ПАКЕТА.html` — полный редакционный банк;
- список авторов и лицензий фотографий.

Добавленные темы: рекламное агентство, белки и углеводы, белорусская армия, устройство и ремонт машин, бухгалтерия, материнство «Грудной карапуз», настольные игры, GTA VI, музыка, общие знания, логика, рыбалка «Клюёт только комар», кондитерские факты и роды «Выход через письку». Визуальные: бытовые предметы, гаражные инструменты и детали, музыкальные инструменты, старая техника, мосты, актёры, рэп новой волны, подсчёт этажей на пяти изображениях пользователя.

`research/extend_pasha.mjs` повторяемо собирает категории 21–43, сохраняя 1–20. `research/download_pasha.py` загружает новые фото с Wikimedia и записывает лицензии. Остальные скрипты исследования — история подготовки; старые `build_pack.py`, `expand_pack.py`, `revise_pack.py` могут перезаписать актуальный пакет.

## Проверки и публикация

```powershell
npm run build
npm test
npm run preview
```

Тесты проверяют игру на 50 и 30 вопросов, случайный набор тем, защиту от повторного начисления, публичный контент и фото. SQL выполняется на локальном Postgres-движке PGlite: пульт без входа, подключение по имени, одновременные заявки, повторные попытки, накопление штрафов, запоздалые запросы, возврат вопроса и сброс партии.

GitHub Actions собирает сайт, запускает тесты и публикует `dist` при пуше в `main`. Settings → Pages → Source: GitHub Actions. Адрес: https://grbchnk.github.io/frage/ . Публичная конфигурация для сборки — `.env.example`.

Совместимый экран для старого телевизора сохранён: `tv.html` или `?compat=1`. Обычный экран на компьютере использует музыку и анимации. Во время вопроса нажмите «± Баллы» в панели ответа, выберите игрока и сумму из списка или введите свою. Верхние карточки показывают стабильные очки и результат последнего ответа. В категориях играет композиция с четырьмя частями, в вопросе — отдельная напряжённая подложка.

«Новая игра» не архивирует прошлую партию: обновляет общее лобби через существующую функцию `quiz_restore`, очищает очки, темы и подключившихся участников. Для сброса сначала читается актуальная версия партии; при конфликте с другим пультом запрос повторяется с новой версией. При ошибке показываются её код и причина, без предположения о правах доступа.
